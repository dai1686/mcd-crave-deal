一句话原理

麦当劳的「套餐」不是固定搭配，而是一组可选槽位——主食 / 小食 / 饮料…… 每个槽位有多个选项，而且很多替换是 +¥0。

所以「想吃 A + B」往往不必单点两次：某个套餐的槽位里可能正好能选到 A 和 B，整体更便宜。 问题是没有人会为了省几块钱，把几十个套餐的槽位挨个点开看一遍。这个 Skill 替你看完了。

它怎么算的

定位门店　query-nearby-stores → 拿到 storeCode
拉实时菜单　query-meals → 当前时段在售商品与价格
心愿匹配　把「咖啡」这类口语匹配到具体商品（含套餐内子项）
拆套餐　query-meal-detail → 展开每个套餐的槽位与可选项
枚举方案　全单点基线 / 各套餐覆盖方案 + 未覆盖心愿补齐
真实算价　calculate-price 逐个算到手价（套餐用 roundList 指定槽位）
输出结果　按到手价排序，标出最省方案与节省金额

关键：calculate-price 支持 roundList，所以「套餐能不能覆盖我的心愿」是算出来的，不是靠菜名猜的。
