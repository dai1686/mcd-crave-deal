# 🍔 麦麦心愿单 · mcd-crave-deal

> 你说想吃什么，它找出**能把你心愿全包住的最便宜吃法**。
> 基于麦当劳中国官方 MCP，全部价格来自官方 `calculate-price` 真实算价，不猜、不估算。

---

## 为什么需要它

麦当劳的「套餐」并不是固定搭配，而是一组**可选槽位**：主食 / 小食 / 饮料……
每个槽位里有多个可选项，而且**很多替换是 +¥0**。

所以：

> 你想吃「麦满分 + 咖啡」，第一反应是单点两件 → ¥20
> 但「吉士蛋麦满分组合」这个套餐的槽位里，正好能同时选到麦满分和小杯咖啡 → **¥12**

差价 ¥8，就是这么来的。问题是——没人会为了省八块钱，把几十个套餐的槽位挨个点开看一遍。
这个 Skill 替你把这件事做完了。

## 安装

### 方式一：作为 WorkBuddy Skill 使用（推荐）

```bash
# 1) 申请 MCP Token（免费，30 秒）
#    打开 https://open.mcd.cn/mcp → 手机号登录 → 控制台 → 激活 → 复制 Token

# 2) 把本仓库放到 WorkBuddy 的 skills 目录
git clone https://github.com/dai1686/mcd-crave-deal.git \
  ~/.workbuddy/skills/mcd-crave-deal

# 3) 配好连接器（把 TOKEN 换成你自己的）
#    配置内容见 mcp-config.example.json
```

然后在 WorkBuddy 里直接说：

> 想吃麦满分、咖啡和薯饼，帮我看看怎么点最省

### 方式二：命令行直接用

```bash
export MCD_MCP_TOKEN=你的Token

python scripts/crave.py --want "吉士蛋麦满分,咖啡" \
                        --city 唐山市 --keyword 华北理工大学
```

零第三方依赖，只用 Python 标准库（Python 3.9+）。

### 参数

| 参数 | 说明 |
|---|---|
| `--want` | 必填。想吃的东西，逗号分隔 |
| `--store` | 门店编码；不给就按位置搜 |
| `--city` / `--keyword` | 门店搜索，默认 唐山市 / 华北理工大学 |
| `--order-type` | 1-到店，2-外送 |
| `--be-type` | 1-到店自取，5-得来速 |
| `--json` | 输出 JSON |
| `--max-combo` | 最多评估几个套餐方案（默认 8） |

## 它怎么算的

1. `query-nearby-stores` → 定位门店
2. `query-meals` → 拉当前时段实时菜单
3. 把心愿模糊匹配到商品（名称包含 + 编辑距离打分）
4. `query-meal-detail` → 展开**每个套餐的槽位与可选项**
5. 枚举方案：全单点基线 / 各套餐覆盖方案（槽位优先选命中心愿的子项）+ 未覆盖心愿补齐
6. `calculate-price` → 对每个方案**真实算价**（套餐通过 `roundList` 指定槽位选择）
7. 按到手价排序，输出最省方案

关键在于 `calculate-price` 支持 `roundList`，所以"套餐能不能覆盖我的心愿"是被**算**出来的，不是靠菜名猜的。

详见 [MCP_INTEGRATION.md](./MCP_INTEGRATION.md)。

- 想看看「MCP 除了查数据还能做什么」的开发者——这是一个把查询能力变成决策能力的例子

---

## 安全与边界

- **只读**：只查询与算价，不会下单、不会领券。说"下单"才会走 `create-order`，且必须先确认门店与价格。
- Token 只从环境变量 `MCD_MCP_TOKEN` 读取，不落盘、不进 Git。
- 菜单随时段变化，结果以调用时刻的实时数据为准；套餐展示价可能含门槛优惠，真实到手价以 `calculate-price` 为准。
